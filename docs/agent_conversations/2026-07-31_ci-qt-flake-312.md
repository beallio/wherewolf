- **Corrected Record & Audit Analysis**:
  1. **Measured Outcome & Deprecation Rationale**: Python 3.12 exhibits a `7 / 32 ≈ 21.9%` segfault rate under pytest + coverage + Qt widget tests in CI, whereas Python 3.14 is clean (`0 / 30` baseline, `0 / 20` timid=false). The root cause remains **unexplained** — Python 3.12 is deprecated to avoid the crash, not because the underlying C/Qt bug was identified or resolved.
  2. **Correction of commit `a913e04`**: Commit `a913e04` attributed the crash to coverage's C tracer under Python **3.14**. That explanation is contradicted by empirical evidence: Python 3.14 measured 0 segfaults across 50 runs (30 baseline + 20 timid=false).
  3. **Timid Setting Resolution**: The round 07 `timid-false` result (`0/10`) was discarded as unverified. In round 09 (B22), conftest instrumentation proved `[PYTEST-COV] ACTIVE COVERAGE TIMID = False` reached pytest during run `30686206502`, resulting in `0 / 20` segfaults. Based on this authoritative measurement, `timid = true` was removed from `pyproject.toml`.
  4. **Residual Risk**: 0/30 baseline and 0/20 timid=false bound Python 3.14's crash rate but do not prove it is zero. A crash rate below ~1-in-30 would not be detected by this sample size. If the defect is a latent Qt-teardown problem that 3.12 merely made more frequent, it could resurface on Python 3.14 under specific thread/event loop timing.
  5. **Second Flake**: `tests/test_app.py::test_app_initialization` intermittently fails with `AppTest script run timed out after 3(s)`. This is unrelated to the native Qt segfault, is in the Streamlit path (slated for removal in Phase 14), and is not fixed here.
  6. **Directional Narrowing**: On Python 3.12, `no-cov` (0/10) and `deselect` widget tests (0/10) are directional results consistent with the crash requiring coverage *and* the Qt widget tests together.
