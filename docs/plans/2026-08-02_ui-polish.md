# Plan: Dialect naming, schema selection, history, shortcuts and About (ui-polish)

## Context

Nine defects reported by the maintainer after running build `e77350f`. Each was traced to
a cause before this plan was written; the file:line references below are verified.

### P1 — translation target names are raw sqlglot identifiers

`main_window.py:668` populates the selector straight from `DIALECT_MODULE_NAMES`, so it
renders `duckdb`, `tsql`, `postgres` in lowercase. The **input** dialect selector uses the
friendly names in `constants.py:DIALECT_MAPPING` (`DuckDB`, `Azure SQL`). The two lists
disagree, and the maintainer could not find Azure SQL in the target list — it is there,
spelled `tsql`.

### P2 — the schema panel cannot be pointed at a dataset

`main_window.py:595-608` sets the panel from whichever `SchemaResult` most recently
arrived. There is no selector, so with `customers` and `loans` loaded the user cannot
choose which to inspect.

### P3 — history rows are hard to tell apart

`widgets/history_dock.py:19` is a `QListWidget` and `_label_for` flattens timestamp and
SQL into one string per row.

### P4 — Ctrl+C does not work in the Translation tab

**Root cause found.** `sql_editor.py:183-185` creates `_copy_action` with
`QKeySequence.StandardKey.Copy`, and `main_window.py:783` adds that action to the **Edit
menu**. A QAction owned by the menubar has window-level shortcut scope, so Ctrl+C anywhere
in the window fires `self.editor.copy()` — copying from the SQL editor even when focus is
in the Translation panel, which is why right-click → Copy works and the shortcut does not.
This is a shortcut-routing bug, not a missing feature.

### P5 — toolbar buttons have no hover text

The round that labelled the comboboxes did not give the toolbar `QAction`s tooltips.

### P6 — the query controls live in a scroll area

`main_window.py:229-237` puts them in a `QScrollArea` inside a second toolbar. That was
the previous round's answer to overflow; the maintainer wants a single toolbar instead.

### P7 — Find/Replace, Select All and Toggle Comment have no shortcuts

`desktop/actions.py` assigns shortcuts only to run, cancel, format, add-datasets and
show-completion.

### P8 — About is wrong and thin

`main_window.py:832-838` currently says GPL-3.0-only **and** mentions the retained
pre-0.6 MIT terms. **Maintainer decision: show GPL-3.0 only** — drop the MIT sentence
from the dialog. This changes the dialog text only; `pyproject.toml` stays
`license = "GPL-3.0-only"` and `LICENSES/MIT-pre-0.6.txt` stays in the distribution
because pre-0.6 code is still under those terms. About must also show the version and
build commit, which `wherewolf.build_identifier()` already returns.

**Maintainer decision: the update check is a config option, default off.**

### P9 — the schema panel could show more, cheaply

It shows Name and Type. `domain/models.py:38` already carries `nullable: bool | None`
which is populated and never displayed — free. The `CatalogEntry` already in memory
carries path and source format. Anything requiring a new scan of the data is not free and
is out of scope for this round.

## Implementation Tasks

One commit per task, TDD, tests reaching the feature from `MainWindow` as a user would.

### Task 1 — friendly dialect names everywhere (P1)

Give the translation target selector the same display names as the input selector, and
make sure every sqlglot dialect the target list offers still appears. `Azure SQL` must be
findable by that name. Do not hand-maintain a 33-entry table: derive display names from
`DIALECT_MAPPING` where one exists and title-case the rest, so a new sqlglot dialect
appears automatically with a reasonable label.

Test that the target list contains `Azure SQL` mapped to data `tsql`, that no visible item
text is bare lowercase where a friendly name exists, and that selecting by display name
still transpiles to the right dialect.

### Task 2 — choose the schema dataset (P2)

Add a dataset selector to the schema panel listing the catalog's aliases, defaulting to
the current one. Selecting an alias shows that dataset's schema. Keep the existing
behaviour where a newly-added dataset populates the panel.

Test that with two datasets loaded, choosing each alias changes the displayed columns —
not merely that a combobox exists.

### Task 3 — readable history (P3)

Replace the single-line list with separate **timestamp** and **query** columns, and
alternating row colours. Keep click-to-restore working, including restoring the catalog.
Truncate long SQL to one line in the cell with the full text available on hover.

Test that the timestamp and the SQL are retrievable as separate cells, that alternating
colours are enabled, and that activating a row still restores the query.

### Task 4 — fix shortcut routing (P4)

Make Ctrl+C, Ctrl+X, Ctrl+V, Ctrl+A act on **the focused widget**, not unconditionally on
the SQL editor. Prefer routing clipboard actions through the focus widget over giving the
editor's actions window scope. The Translation panel and the results grid must both copy
their own content.

Test with focus set to the translation panel that a copy action places the *translation*
text on the clipboard, and with focus in the editor that it places the *editor* selection
— the pair is the point; either alone would pass today or after a naive fix.

### Task 5 — toolbar tooltips (P5)

Every toolbar `QAction` gets a tooltip saying what it does, including its shortcut where
one exists. Test by iterating the toolbar's actions and asserting each has non-empty
tooltip text, so a newly added button cannot slip through unlabelled.

### Task 6 — one toolbar, no scroll area (P6)

Remove the `QScrollArea` and present the query controls in a single toolbar. If they do
not fit at a narrow width, use a toolbar extension/overflow button (Qt provides this) or
move the least-used controls into a menu — do **not** reintroduce a scroll area. Say in
the session log which approach you chose.

Test that no `QScrollArea` exists in the toolbar hierarchy and that every named control is
still reachable from `MainWindow`.

### Task 7 — shortcuts for the remaining edit commands (P7)

Find/Replace → `Ctrl+F`, Select All → `Ctrl+A`, Toggle Comment → `Ctrl+/`. Ensure these do
not collide with existing bindings and that they respect the focus routing from Task 4.
Test that each action reports the expected shortcut and that triggering it changes editor
state.

### Task 8 — About dialog (P8)

Show GPL-3.0-only **only** — remove the MIT sentence from the dialog. Include
`build_identifier()` so the version and build commit are visible. Do not change
`pyproject.toml`, `LICENSE`, or remove `LICENSES/MIT-pre-0.6.txt`: pre-0.6 code remains
under those terms and the distribution must keep the file.

Add an update check as a **configuration option defaulting to off**, persisted through
`SettingsService` and exposed in Preferences. When disabled — the default — the app must
make **no network call whatsoever**. When enabled, the check runs off the UI thread, never
blocks startup, and fails silently when offline.

Test: the About text contains the version, the build commit and GPL-3.0-only, and does not
mention MIT; the setting defaults to off; and with it off, no network call is attempted
(assert against a faked network layer that records calls, so "no traffic" is actually
verified rather than assumed).

### Task 9 — richer schema panel (P9)

Add a **Nullable** column — `ColumnSchema.nullable` is already populated and discarded
today. Add the column's ordinal position, and show the source file and format from the
`CatalogEntry` alongside the alias. Handle `nullable is None` (unknown) distinctly from
`False`.

Do **not** add anything requiring a fresh scan of the data, such as row counts or
distinct-value statistics. Test all three of nullable true/false/None.

### Cross-cutting requirements

- Do not weaken, skip or delete existing tests.
- Do not remove `timid = true`, the `pyarrow` import, or the overwrite confirmation.
- Do not change `EngineKind`, or the *values* in `DIALECT_MAPPING` (display names may gain
  entries; the sqlglot identifiers they map to must not change).
- Do not bump the version, tag, or touch `main`.
- Run `./run.sh uv run ty check .` (whole repo) before committing.
